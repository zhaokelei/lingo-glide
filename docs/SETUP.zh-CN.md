# 安装与使用

[返回中文说明](README.zh-CN.md)

## 1. 目录怎么摆

模型目录（下文用 `MODEL_DIR` 指代）和仓库是分开的，权重不进 git：

```
MODEL_DIR/
├── bin/llama-b12125/llama-server     llama.cpp 二进制
├── models/Hy-MT2-1.8B-Q4_K_M.gguf    模型权重，约 1.1 GB
├── logs/                             运行日志与 PID，脚本自动创建
├── run.sh                            从仓库 scripts/ 复制
├── 启动翻译模型.command               从仓库 scripts/ 复制
└── 停止翻译模型.command               从仓库 scripts/ 复制
```

三个脚本靠自身所在目录找 `models/` 和 `bin/`。要放到别处，先 `export TRF_HOME=<模型目录>`，端口用 `TRF_PORT` 改。

## 2. 启动服务

双击「启动翻译模型.command」，或终端里：

```
cd MODEL_DIR
./run.sh 1.8b 8080
```

脚本会等健康检查通过再打开翻译网页。终端窗口关掉服务仍在后台，PID 写在 `logs/hy-mt.pid`。

验证：

```
curl http://127.0.0.1:8080/v1/models
# 期望返回 data[0].id = hy-mt2

curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"hy-mt2","messages":[{"role":"user","content":"把这句中文翻成英文：你现在在做什么？"}],"temperature":0.3,"max_tokens":64}'
```

停止：双击「停止翻译模型.command」。它只杀 PID 文件里记录的进程，不会碰其它 llama.cpp 实例。

## 3. 加载扩展

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）。
2. 打开「开发者模式」。
3. 「加载已解压的扩展程序」，选仓库里的 `extension/` 目录。
4. 如果之前加载过 `dist/translate-ext.zip` 解压出来的目录，选那个目录也行，但改了代码要重新解压。

改代码后的固定动作：扩展页点「刷新」，再刷新要测试的网页。扩展不会热更新，旧页面里的 content script 也不会自己换。

## 4. 第一次检查

1. 打开设置页，确认服务地址是 `http://127.0.0.1:8080/v1`、模型名是 `hy-mt2`。
2. 打开任意网页，在输入框里打一句中文，连按三次空格。
3. 看到「翻译中…」后变成译文，说明服务、扩展、回填三条链路都通了。

右下角悬浮球只在英文页、且目标语言不是英文时自动提示翻译；其它情况点球手动翻译。

## 5. 常见问题

**设置页显示「服务未连接」**：先 `curl http://127.0.0.1:8080/v1/models`。没有响应就启动服务；返回 404 说明模型名不匹配，检查 `--alias`。

**端口被占**：`lsof -nP -iTCP:8080 -sTCP:LISTEN`。如果是旧实例，用停止脚本；不是本脚本启动的，不要直接 `kill -9`，先确认是什么进程。脚本检测到端口已有服务时会直接用，不会覆盖。

**三空格没反应**：先确认扩展在页面里加载了（设置页的调试开关打开后，页面控制台会打印 `[trf-fill]` 时间线）。站点把 keydown 拦截掉的情况，扩展已经在捕获阶段处理；如果站点在 `beforeinput` 阶段清空内容，换快捷键试。

**输入框没变成译文**：右下角应该出现译文卡片，说明三级兜底都失败。把调试时间线（`fillTrace` 输出）留存，按 `engine` 字段判断是编辑器类型没识别还是写入被拦。

**整页翻译很慢**：CPU 推理的正常速度。把「每批字符数」调小可以更快看到第一段，总耗时不会明显下降。

**想清缓存**：设置页「缓存」分组里有条数和清除按钮。换提示词版本后旧缓存不会命中，不必手动清。
